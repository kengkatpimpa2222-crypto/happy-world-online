## สรุปสั้น

ของที่มีแข็งแรงกว่าที่คิด: **บัญชี, เมืองออนไลน์ realtime, เพื่อน/บล็อก/รายงาน, ร้านค้ามีชีวิตที่ขายตอนออฟไลน์, เทศกาล, เมืองที่โตตามเวลาและอากาศ, กระเป๋าเงินแบบ ledger กันเงินซ้ำ**
คือแกน "ชีวิตในเมือง + ธุรกิจ" พร้อมแล้วราว 70%

ช่องว่างใหญ่ที่สุดคือ **วงจรที่แผนบอกว่าต้อง "เชื่อมกันจริง" ยังไม่เชื่อม**:
ตอนนี้ร้านเติมสินค้าด้วยการจ่าย Gold ซื้อจากระบบ (`business.service.ts:82` restock) ไม่มีวัตถุดิบ ไม่มีการคราฟต์ ไม่มีการผจญภัย
เงินที่หาได้ก็ยังเอาไปแต่งบ้านไม่ได้ เพราะ **บ้านมีตารางในฐานข้อมูลแต่ไม่มี API** (`PlayerHome`, `HomeFurniture` ใน `schema.prisma` แต่ไม่มี controller ไหนอ้างถึง)

ดังนั้นงานที่คุ้มที่สุดไม่ใช่เพิ่มระบบใหม่ทีละก้อน แต่คือ **ต่อสาย 3 เส้น**: ผจญภัย → วัตถุดิบ → คราฟต์ → ร้าน → เงิน → บ้าน/แฟชั่น

## หลักการวางแผนต่อ

1. **ต่อของเดิม ไม่เขียนใหม่** ทุกเฟสด้านล่างเพิ่มของเข้าไปใน module ที่มี: wallet ledger, quest objective, `BUSINESS_PRODUCTS`, `ItemCategory`, โซนเมือง, ปฏิทินเทศกาล
2. **ต่อสายก่อน แล้วค่อยเพิ่มความลึก** วงจรครบหนึ่งรอบแบบตื้น ดีกว่าระบบลึกระบบเดียว
3. **RPG แบบ cozy ไม่ใช่ action** การต่อสู้แบบเรียลไทม์บนมือถือที่เซิร์ฟเวอร์ต้องตรวจทุกครั้งเป็นงานหนักที่สุดในเกมออนไลน์ เสนอ "การสำรวจ" ที่เซิร์ฟเวอร์คำนวณผล (แบบเดียวกับที่ร้านคำนวณลูกค้า NPC อยู่แล้วใน `living-shop-sim.ts`) ซึ่งกันโกงได้ตั้งแต่ต้นและเล่นได้ 5 นาที
4. **ไม่ขายพลัง** สิ่งที่ขายได้คือรูปลักษณ์ ความสะดวกที่ไม่กระทบเศรษฐกิจ และ Season Pass ที่มีแทร็กฟรี
5. **วัดก่อนขาย** ระบบ analytics ต้องมาก่อนเปิดขายของ ไม่งั้นจะไม่รู้ว่าราคาทดลองได้ผลไหม

### Phase 8 — วงจรวัตถุดิบ: สำรวจ → คราฟต์ → วางขาย (แนะนำให้ทำต่อทันที)

เป้าหมาย: ปิดช่องว่างที่ใหญ่ที่สุด ให้ "เล่น RPG แล้วได้ของไปทำธุรกิจ" เป็นจริง

- **วัตถุดิบเป็นไอเทม**: เพิ่ม `ItemCategory.MATERIAL` (เช่น มะนาว แป้ง ใบชา ดอกไม้ป่า เนื้อ) ใช้ `PlayerInventory` เดิม และเพิ่มตาราง ledger ของไอเทม (`InventoryTransaction` มี `idempotencyKey` แบบเดียวกับ wallet) เพื่อกันไอเทมซ้ำตั้งแต่วันแรก
- **การสำรวจ (Expedition) แบบ cozy RPG**: ประตูในโซน `ACTIVITY` พาไปสถานที่ 3 แห่ง (สวนผลไม้, ป่าดอกไม้, ถ้ำเล็ก) ผู้เล่นเลือกจุดหมาย ใช้เวลา 3-10 นาที ระหว่างทางเจอเหตุการณ์ (สัตว์ป่าขวางทาง, ต้นไม้ล้ม) ที่ตัดสินด้วยค่าสถานะ + ตัวเลือก ผลคำนวณที่เซิร์ฟเวอร์จาก seed เดียวกับร้าน จึงตรวจย้อนได้ ไปกับเพื่อนในช่วงอายุเดียวกันได้ 2-4 คน (ปาร์ตี้เล็กครั้งแรก)
- **ค่าสถานะ + XP จากหลายทาง**: XP ได้จากการสำรวจ การคราฟต์ และการขาย ไม่ใช่แค่เควสต์ เพิ่มทักษะชีวิต 3 สาย (นักสำรวจ, เชฟ/ช่าง, พ่อค้า) แทน skill tree ต่อสู้ แต่ละสายปลดล็อกสูตรและพื้นที่ใหม่
- **คราฟต์**: สูตรใน `shared-contracts` (เช่น มะนาว 2 + น้ำตาล 1 → LEMONADE 5) ผลลัพธ์เข้า `BusinessInventory` เดิมโดยคิด `avgUnitCost` จากมูลค่าวัตถุดิบ ร้านขายได้ทันทีโดยไม่ต้องแก้ระบบขาย restock ด้วย Gold ยังอยู่เป็นทางลัด แต่ของคราฟต์เองได้กำไรมากกว่า ผู้เล่นจึงมีเหตุผลออกไปสำรวจ
- **เควสต์ใหม่**: objective `EXPEDITION_COMPLETE`, `CRAFT_ITEM`, `GATHER_MATERIAL` ต่อเข้า `quests.recordEvent()` เดิม
- **มินิเกมแจกวัตถุดิบ**: ใช้ ledger type `MINIGAME_REWARD` ที่มีอยู่แล้ว
- สิ่งที่ไม่ทำในเฟสนี้: ต่อสู้แบบเรียลไทม์ บอส อุปกรณ์ที่เพิ่มพลัง

ตัวชี้วัดของเฟส: ผู้เล่นที่ถึงเลเวล 3 ทำวงจร สำรวจ → คราฟต์ → ขาย ครบหนึ่งรอบอย่างน้อย 60% (วัดได้หลัง Phase 10)

### Phase 9 — บ้านของฉันและการเยี่ยมบ้าน

เป้าหมาย: ให้เงินที่หามีที่ใช้ที่รู้สึกเป็นของตัวเอง ใช้ของที่มีอยู่แล้วในฐานข้อมูลเกือบทั้งหมด

- API บ้าน: ดูบ้าน, วาง/ย้าย/หมุน/เก็บเฟอร์นิเจอร์ (ใช้ `HomeFurniture` และ `layoutVersion` เดิมเป็น optimistic lock), เปลี่ยนพื้น/ผนัง/ธีม
- ฉากบ้านในเกม (สร้างด้วยโค้ดแบบเดียวกับ `CityBuilder.cs`) + โหมดจัดบ้านแบบลากวางบนกริด
- เยี่ยมบ้านเพื่อนจากโซน `HOMES` (เฉพาะเพื่อนและช่วงอายุเดียวกัน), ปุ่ม "ชอบบ้านนี้" แบบไม่ต้องพิมพ์
- คราฟต์เฟอร์นิเจอร์จากวัตถุดิบของ Phase 8 (สูตรชุดเดียวกัน)
- โหมดถ่ายรูป: ซ่อน UI + ท่าทาง 3-5 ท่า บันทึกลงเครื่อง (ไม่อัปโหลด จึงไม่มีความเสี่ยงเรื่องรูปของเด็ก)
- ทำให้เควสต์ `PLACE_FURNITURE` ที่ค้างอยู่ใช้งานได้จริง

### Phase 10 — พร้อมทดสอบกับคนจริง (90 วันแรก วันที่ 1-30)

เป้าหมาย: เปิดทดสอบ 20-50 คนแล้ววัดตัวเลขในข้อ 5 ของแผนได้จริง

- **Analytics ฝั่งเซิร์ฟเวอร์**: ตาราง `GameEvent` (ชื่อ event, userId, เวลา, ค่า) บันทึกจาก service เดิม: สร้างตัวละครสำเร็จ, จบเควสต์แรก, เปิดร้านครั้งแรก, สำรวจครั้งแรก, เข้าเกมแต่ละวัน; script สรุป D1/D7/funnel เป็น CSV ไม่ส่งข้อมูลให้บุคคลที่สาม ไม่เก็บข้อมูลระบุตัวตนเพิ่ม
- **เป้าหมายรายวันที่ไม่ลงโทษ**: 3 งานเล็กต่อวัน ถ้าไม่เข้าเล่น งานจะสะสมไว้สูงสุด 3 วัน (rest bonus) ไม่มี streak ที่ขาดแล้วเสียของ ตรงกับแผนข้อ 2
- **หน้าแอดมินขั้นต่ำ**: ดูรายงาน, ระงับบัญชี, บังคับเปลี่ยนชื่อ (มี `AuditLog` อยู่แล้ว)
- **Load test realtime**: บอท Socket.IO 200-500 ตัวเดินในเมือง ต่อยอดจาก `scripts/market-bot.js`
- **Backup/restore**: เขียนขั้นตอนและซ้อมกู้ Postgres จริงหนึ่งครั้ง
- ส่ง APK ทดสอบผ่าน Google Play Internal Testing (thread Unity build/QA ช่วยได้)

### Phase 11 — ตลาดผู้เล่นและกิลด์ (วันที่ 31-60)

เป้าหมาย: เศรษฐกิจที่มีความต้องการจริงระหว่างผู้เล่น และกลุ่มที่อยากกลับมาเจอกัน

- ผู้เล่นซื้อสินค้าจากแผงของผู้เล่นอื่นได้ (เงิน Gold โอนผ่าน ledger ทั้งสองฝั่งใน transaction เดียว + ledger ไอเทมจาก Phase 8)
- ตลาดกลางสำหรับวัตถุดิบ แบบตั้งราคาขาย/ซื้อ มีเพดานราคาและภาษีตลาดเล็กน้อยเป็นตัวดูดเงินออกจากระบบ ป้องกันเงินเฟ้อ
- ผู้เล่นต่างช่วงอายุซื้อของกันได้ผ่านตลาด แต่ไม่เห็นชื่อ/คุยกัน (คงกฎ `canInteract()`)
- **กิลด์แบบ "ชมรม"**: 5-20 คน, เป้าหมายชมรมรายสัปดาห์ที่ต่อจากเป้าเทศกาลเดิม, บ้านชมรมใช้ระบบบ้านของ Phase 9
- สัตว์เลี้ยงตัวแรก (ฟรีจากเควสต์) ติดตามตัวละคร ช่วยหาวัตถุดิบเล็กน้อยระหว่างสำรวจ เท่ากันทุกตัว

### Phase 12 — รายได้แบบไม่ Pay-to-Win (วันที่ 61-90)

ทำหลัง Phase 10 เท่านั้น เพราะต้องมีตัวเลขการกลับมาเล่นก่อนตั้งราคา

- เปิด Google Play Billing จริง: acknowledge/consume, RTDN และ Voided Purchases เพื่อดึงคืนเมื่อคืนเงิน (ใช้สถานะ `REFUNDED` และ ledger `IAP_REFUND` ที่เตรียมไว้)
- **ล็อกการซื้อเงินจริงตามอายุ**: ผู้เล่น `UNDER_13` ซื้อได้เมื่อมี `parentalConsentAt` เท่านั้น และตั้งเพดานต่อเดือน
- ร้านแฟชั่น/ของแต่งบ้าน 5-10 รายการ ราคาทดลอง 19-299 บาทตามแผน ขายตรงไม่สุ่ม
- **Season Pass**: ยาวเท่ารอบฤดูไทย (`city-time.ts`) แทร็กฟรีให้ทุกคน แทร็กพรีเมียม 99-199 บาท แต้มได้จากการเล่นปกติ ได้แต่ของตกแต่ง/ท่าทาง/สัตว์เลี้ยงหน้าตาพิเศษ
- VIP รายเดือน: ใช้ตาราง `Subscription` ที่มีอยู่ ให้แค่ความสะดวกที่ไม่กระทบตลาด เช่น ช่องจัดบ้านเพิ่ม กรอบรูป ชื่อสีพิเศษ ไม่เพิ่มรายได้ร้านหรือ drop rate
- ไม่มีกล่องสุ่มเงินจริงตามที่แผนแนะนำ
