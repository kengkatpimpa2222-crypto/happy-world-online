ปิดข้อ "งานหนึ่งระบบ" ของต้นแบบใน GDD ตอนนี้ครบ 5/5: เมือง ✅ ผู้เล่นหลายคน ✅ บ้าน ✅ งาน ✅ วงจรผลิตถึงขาย ✅

## ไอเดียหลัก: งานที่สอนทักษะจริง ไม่ใช่กดรอเวลา

เกมแนว life sim ส่วนใหญ่ทำงานเป็น "กดแล้วรอ" ซึ่งไม่ได้อะไรนอกจากเงิน เป้าหมายข้อ 3 ของโปรเจกต์คือ "เรียนรู้จากการเล่น" เฟสนี้จึงให้ทุกกะเป็น 5 สถานการณ์สั้น ๆ จากชีวิตจริง ทำเสร็จใน 1-2 นาที (เข้ากับ session 5-15 นาที)

| งาน | ที่ทำงาน | ฝึกอะไร | ตัวอย่าง |
|---|---|---|---|
| พนักงานแคชเชียร์ | มินิมาร์ทหน้าลานเมือง (PLAZA) | ทอนเงินด้วยเหรียญ/แบงก์ไทยจริง ใช้ชิ้นน้อยที่สุดได้ทิป | ลูกค้าซื้อน้ำดื่ม 7 + ขนมปัง 15 จ่ายแบงก์ 50 → ทอน 20 + 5 + 2 + 1 |
| ผู้ช่วยชาวสวน | สวนลุงมี (เขตชนบท ใหม่) | หารแล้วปัดขึ้น ลังที่ไม่เต็มก็ต้องใช้ | เก็บได้ 5, 5, 1 กก. ลังละ 5 กก. → 3 ลัง ไม่ใช่ 2 |
| พนักงานแพ็กของ | โรงงานแพ็กสินค้า (เขตอุตสาหกรรม ใหม่) | วางแผน: วิธีหยิบกล่องใหญ่ก่อนไม่ใช่วิธีที่ดีที่สุดเสมอ | ออร์เดอร์ 12 ชิ้น กล่อง 9/4/1 → 4+4+4 (3 กล่อง) ดีกว่า 9+1+1+1 (4 กล่อง) |

- **ตอบผิดไม่โดนหักเงิน** แค่ไม่ได้ค่าแรงข้อนั้น แล้วสลิปค่าแรงอธิบายเฉลยทุกข้อ เช่น "✗ ต้องทอน 28 บาท (50 − 22) คุณทอน 25 บาท · ทำแบบนี้: 20 + 5 + 2 + 1" ความผิดพลาดกลายเป็นบทเรียน
- **สลิปค่าแรง** แยกบรรทัด: ค่าแรง, ทิปทำได้ดีที่สุด, โบนัสถูกครบกะ, โบนัสทักษะ เด็กได้เห็นว่ารายได้มาจากไหน (ความรู้เรื่องเงินแบบเบา ๆ)
- **ทักษะพนักงาน (WORKER)** ใช้ตาราง `player_skills` เดิม เลเวลละ +5% ค่าแรง Lv 2 ปลดล็อกงานแพ็กของ (ประมาณ 4 กะที่ทำดี)
- **งานสวนจ่ายเป็นผลผลิตด้วย** (มะม่วง/มะพร้าว/ข้าวเหนียว 2 ชิ้นถ้าถูก ≥ 3 ข้อ) ต่อเข้ากับงานฝีมือ Phase 9 ได้ทันที: ทำงานที่สวน → ได้วัตถุดิบ → แปรรูปข้าวเหนียวมะม่วง → ขายที่ร้าน
- **ไม่บังคับเข้าทุกวัน**: วันละ 8 กะที่ได้ค่าแรง เกินนั้นเป็น "กะฝึกฝน" ตรวจและเฉลยเหมือนเดิมแต่ไม่ได้ทอง ข้ามวันไม่เสียอะไร
- **ภารกิจรายวันใหม่** "ทำงานพาร์ตไทม์ให้ครบ 1 กะ" (`d_job_1`) ผ่าน hook `recordEvent` เดิม ไม่ต้องแก้ระบบภารกิจ

### โลกที่เดินเข้าไปได้ (GDD เขต D และ E)

- เขต **ชนบท (COUNTRYSIDE)** 60×50 และ **เขตอุตสาหกรรม (INDUSTRIAL)** 50×40 เพิ่มใน `CITY_ZONES` ประตูอยู่มุมล่างซ้าย/ขวาของลานกลางเมือง ใช้ระบบห้อง/shard/ช่วงอายุเดิมทั้งหมด (server ไม่ต้องแก้ realtime)
- แต่ละที่ทำงานมีอาคาร (มินิมาร์ท, โรงนา + แปลงผัก + ลัง, โรงงาน + สายพาน) ป้าย "รับสมัคร..." และวงกลมสีส้มให้ยืน ยืนบนวงกลมแล้วปุ่ม "ทำงาน: พนักงานแคชเชียร์" ขึ้น (กด E บน PC)
- ในชนบทมี **ประตูไม้ "ทางไปจุดสำรวจ"** เปิดหน้าออกสำรวจของ Phase 9 (ปุ่มเดิมบน HUD ยังอยู่)
- ชนบทมีต้นไม้มากขึ้น เขตอุตสาหกรรมพื้นปูและมีโกดังมากกว่า ต้นไม้สุ่มหลบที่ทำงาน
- หน้า "เมือง" มีแถว "งานพาร์ตไทม์" เปิดบอร์ดงานได้จากทุกที่ ปุ่ม "ไปชนบท/ไปเขตอุตสาหกรรม" พาไปโซนนั้น (เริ่มกะได้เฉพาะตอนยืนที่ป้าย)

### หน้าจอทำกะ (Unity)

- ทีละงาน: โจทย์ + บรรทัดนับให้ ("ทอนแล้ว 30 บาท (3 ชิ้น): 20 + 10") บรรทัดนี้ช่วยนับเท่านั้น **ไม่บอกว่าถูกหรือผิด** server ตัดสินตอนส่งงาน
- แคชเชียร์: ปุ่มแบงก์ 100/50/20 แถวบน ปุ่มเหรียญ 10/5/2/1 แถวล่าง แตะเพื่อยื่นเงิน ปุ่ม "ล้าง"
- สวน/โรงงาน: ปุ่ม − / + ใหญ่ ๆ ต่อขนาดกล่องหรือจำนวนลัง
- "◀ ก่อนหน้า" / "ถัดไป ▶" / "ส่งงาน" แล้วโชว์สลิปค่าแรงพร้อมเฉลยทุกข้อ ปิดแอปกลางกะแล้วกลับมา กดเริ่มงานเดิมได้กะเดิมกลับมา (คำตอบที่กรอกไว้หาย ต้องทำใหม่)

## ความน่าเชื่อถือ

| ความเสี่ยง | วิธีกัน | ทดสอบ |
|---|---|---|
| ปลอมคำตอบ/ปลอมค่าแรง | server สร้างโจทย์จาก seed ที่ไม่ส่งออก ตรวจทุกข้อเอง client ส่งแค่ตัวเลขคำตอบ schema `.strict()` | e2e: เฉลย/ผิด/ถูกแต่ไม่ดีที่สุด/รูปแบบผิด |
| ส่งงานซ้ำ / พร้อมกันหลายครั้ง | ล็อกแถวผู้เล่น + แถวกะ, `ACTIVE → DONE` ครั้งเดียว, ledger key `job:<shiftId>:GOLD` | e2e: ส่ง 8 ครั้งพร้อมกัน จ่ายครั้งเดียว ส่งคำตอบใหม่ทีหลังได้สลิปเดิม |
| เปิดหลายกะพร้อมกันเพื่อเลี่ยงโควตา | partial unique index กะ ACTIVE ได้ทีละกะ + นับโควตาใน transaction ที่ล็อก | e2e: start 6 ครั้งพร้อมกันได้กะเดียว, 8 กะแล้วกะที่ 9 ไม่จ่าย |
| บอทส่งคำตอบทันที | ต้องใช้เวลาอย่างน้อย 2 วินาทีต่องาน (`JOB_SHIFT_TOO_EARLY`) + เพดานวันละ 8 กะ | e2e + C# integration |
| กะค้างตลอดไป | เกิน 15 นาที = void (`JOB_SHIFT_EXPIRED`) และไม่บล็อกกะใหม่ | e2e |
| ส่งกะของคนอื่น | ค้นด้วย (id, ผู้เล่น) → 404 | e2e |
| เงินเฟ้อ | ค่าแรงสูงสุดทั้งวัน (Lv 10, ถูกหมด) ไม่เกิน 1,000 ทอง (unit test กันไว้) Lv 1 แคชเชียร์ประมาณ 480/วัน | unit |
| นาฬิกาเครื่อง | วันไทยใช้นาฬิกา server ตัวเดียวกับรางวัลรายวัน (`DAILY_CLOCK_OFFSET_HOURS` ห้ามใช้ใน production อยู่แล้ว) | e2e ข้ามเที่ยงคืน |

## จุดที่ควรรู้ / ปัญหาที่เหลือ

- **server ไม่ได้ตรวจว่าผู้เล่นยืนอยู่ที่ป้ายจริง** (client บังคับเอง) เพราะ presence อาจหายตอนเน็ตหลุด เลือกให้เล่นต่อได้ก่อน ถ้าจะบังคับต้องอ่านโซนจาก presence store ตอน `start`
- บอทที่เขียนโปรแกรมแก้โจทย์ได้ทุกข้อ (เป็นเลขง่าย) ตัวจำกัดคือเวลาขั้นต่ำและเพดาน 8 กะ/วัน ค่าเสียหายสูงสุดต่อบัญชีจึงจำกัด
- อาคารที่ทำงานเป็น primitive + โมเดล Kenney ที่มีอยู่ ยังไม่มีโมเดลเฉพาะ
- แคชเชียร์ไม่มี "แตะเพื่อเอาคืนทีละเหรียญ" มีแค่ "ล้าง" (ตั้งใจให้ UI ง่าย)
- ยังไม่ได้ย้ายงานฝีมือไปเป็นสถานที่ในเขตอุตสาหกรรม และยังไม่มี `production_jobs` แบบใช้เวลา
- เปลี่ยน pool ภารกิจรายวัน (เพิ่ม `d_job_1`) ทำให้ชุดภารกิจของวันที่ deploy อาจสลับ ควร deploy หลังเที่ยงคืนตามที่ Phase 11 แนะนำ
- `docs/openapi.json` ยังไม่ได้ generate ใหม่ (ค้างมาตั้งแต่ Phase 6) endpoint อยู่ใน `docs/api.md`
